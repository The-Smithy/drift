# Drift — Agent Integration Guide

This document explains how AI coding agents should use Drift indexes to reduce token usage and find code faster.

## What is the index?

A `.drift-index.json` file in the repo root, generated by `drift index .`. It contains:

- **`symbol_index`** — a reverse lookup from symbol name to `{file, line, kind, exported}`
- **`files`** — per-file symbol lists and import graphs
- **`tests`** — test suites and individual test cases with line numbers

## When to use the index

**Use it FIRST when you need to:**

- Find where a function, class, type, constant, or other symbol is defined
- Understand what a file exports without reading it
- Find which files import a given module
- Locate tests for a specific module or feature
- Get an overview of a file's API surface

**Use Grep/Read instead when:**

- The index doesn't exist or `generated_at` is old
- You need the actual implementation code, not just the location
- You're searching for string literals, comments, or non-symbol patterns
- You're looking for something added after the last index run

## How to use it

### Finding a symbol

Read `.drift-index.json` and look up the name in `symbol_index`:

```json
{
  "symbol_index": {
    "UserController": [
      {"file": "src/controllers/user.ts", "line": 12, "kind": "class", "exported": true}
    ]
  }
}
```

Then read `src/controllers/user.ts` starting at line 12. No grep needed.

### Browsing a file's symbols

Look up the file path in `files`:

```json
{
  "files": {
    "src/controllers/user.ts": {
      "lang": "typescript",
      "lines": 142,
      "symbols": [
        {"name": "UserController", "kind": "class", "line": 12, "exported": true},
        {"name": "getUser", "kind": "function", "line": 45, "exported": true, "parent": "UserController"},
        {"name": "createUser", "kind": "function", "line": 78, "exported": true, "parent": "UserController"}
      ],
      "imports": [
        {"source": "../models/User", "names": ["User", "UserInput"]},
        {"source": "../lib/auth", "names": ["requireAuth"]}
      ]
    }
  }
}
```

This tells you the file's API surface, what it depends on, and exactly where each piece is — without reading the file.

### Finding tests

Look up test files in `tests`:

```json
{
  "tests": {
    "tests/controllers/user.test.ts": {
      "framework": "vitest",
      "suites": [
        {
          "name": "UserController",
          "line": 5,
          "cases": [
            {"name": "creates a user with valid input", "line": 12},
            {"name": "rejects duplicate email", "line": 28},
            {"name": "returns 404 for missing user", "line": 41}
          ]
        }
      ]
    }
  }
}
```

### Tracing dependencies

To find what depends on a module, scan `files.*.imports` for entries whose `source` matches the module path:

```
For each file in files:
  For each import in file.imports:
    If import.source contains "auth" → this file depends on the auth module
```

## Symbol kinds

| Kind | Languages | Description |
|------|-----------|-------------|
| `function` | All | Functions, methods, async functions |
| `class` | TS/JS, Python | Class definitions |
| `interface` | TS | Interface definitions |
| `type` | TS, Rust | Type aliases |
| `enum` | TS, Rust | Enum definitions |
| `const` | TS/JS, Python, Rust, SQL | Constants, statics, indexes, policies |
| `struct` | Rust | Struct definitions |
| `trait` | Rust | Trait definitions |
| `impl` | Rust | Impl blocks |
| `macro` | Rust | Macro definitions |
| `module` | Rust | Module declarations |
| `table` | SQL | CREATE TABLE |
| `view` | SQL | CREATE VIEW (including materialized) |
| `procedure` | SQL | CREATE PROCEDURE |
| `trigger` | SQL | CREATE TRIGGER |

## Symbol properties

| Property | Type | Description |
|----------|------|-------------|
| `name` | string | Symbol name |
| `kind` | string | One of the kinds above |
| `line` | int | 1-indexed line number |
| `exported` | bool | Whether the symbol is public/exported |
| `parent` | string or null | Parent symbol (e.g., class name for methods) |
| `async` | bool | Whether the function is async |
| `decorators` | string[] | Python decorators (Python only) |

## Compact mode

When the index was generated with `--compact`:

- Null/false fields are omitted (no `"exported": false`, no `"parent": null`)
- JSON has no whitespace
- `symbol_index` only contains exported symbols

The structure is identical — just smaller. All lookups work the same way.

## Keeping the index fresh

The index has a `generated_at` timestamp. If it's more than a day old, or you know files have changed since then, re-run:

```bash
drift index . --compact
```

For CI/CD, add this to your pipeline to keep indexes current:

```bash
pip install drift-index
drift index . --compact
```

## Integration examples

### Claude Code skill (automatic)

Run `drift install .` to add a `.claude/skills/drift.md` file. Claude Code will load it automatically when working on supported file types.

### AGENTS.md / Cursor rules / Codex

Add to your agent instructions:

```
Before searching for code, read .drift-index.json if it exists.
Use symbol_index to find definitions directly instead of grepping.
Use the tests section to find test locations.
Use files.*.imports to trace dependencies.
```

### Programmatic access

```python
import json

with open(".drift-index.json") as f:
    index = json.load(f)

# Find a symbol
locations = index["symbol_index"].get("MyClass", [])
for loc in locations:
    print(f"{loc['file']}:{loc['line']} ({loc['kind']})")

# List a file's exports
file_data = index["files"]["src/main.ts"]
exports = [s for s in file_data["symbols"] if s.get("exported")]
```
