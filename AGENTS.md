# Drift: Agent Integration Guide

This document explains how AI coding agents should use Drift to reduce token usage and find code faster.

## What is the index?

A `.drift-index.json` file in the repo root, generated by `drift index .`. It contains:

- **`symbol_index`**: a reverse lookup from symbol name to file and line range
- **`files`**: per-file symbol lists and imports
- **`tests`**: test suites and individual test cases with line numbers

## The one rule: query it, don't read it

A large repo's index runs to hundreds of kilobytes, and with `--compact` it is a single line. Reading or grepping the file returns all of it, which can cost more tokens than the search you were avoiding.

Use the lookup commands below. Each one prints only what you asked for.

## When to use it

**Use Drift first when you need to:**

- Find where a function, class, type, constant, table or other symbol is defined
- See what a file defines and exports without reading it
- Find which files import a given module
- Locate the tests for a module or feature

**Use Grep or Read instead when:**

- The index doesn't exist, or `generated_at` is older than your recent changes
- You need the implementation, not the location
- You're searching for call sites. The index records definitions, not usages
- You're searching for string literals or comments

## How to use it

### Finding a symbol

```console
$ drift query UserController
  class        UserController  src/controllers/user.ts:12-140 (exported)
```

Each line shows the kind, name, `file:start-end`, whether it is exported, and its parent if it has one. Then read only that range of the file.

Exact names match first. If there are none, the query matches case-insensitive substrings. It exits with code 1 when nothing matches. It finds private symbols too, even in a compact index.

### Browsing a file's symbols

```console
$ drift outline src/controllers/user.ts
src/controllers/user.ts  typescript, 142 lines
  class        UserController  12-140 (exported)
  function     getUser  45-60 (exported) in UserController
Imports:
  ../models/User: User, UserInput
  ../lib/auth: requireAuth
```

This gives you the file's API surface and dependencies without reading the file.

The path can be absolute, relative to the repo root, or a trailing part such as `controllers/user.ts`. If a trailing part fits several files, the command lists them and exits with code 1.

### Finding tests

```console
$ drift tests
  tests/controllers/user.test.ts  vitest  2 tests
2 tests across 1 files

$ drift tests duplicate
tests/controllers/user.test.ts  vitest
  UserController  (line 5)
    28  rejects duplicate email
```

The text is matched case-insensitively. A match on a file path shows the whole file, a match on a suite name shows the whole suite, and a match on a case name shows just that case. The command exits with code 1 when nothing matches.

Suites are a flat list, even when `describe` blocks nest. Each case belongs to its innermost suite. Cases outside any suite go in a suite named `(root)` for JS and TS, or `(module)` for Python and Rust.

The framework is one of `vitest`, `jest`, `mocha`, `playwright`, `node-test`, `cypress`, `pytest`, `unittest`, `cargo-test` or `unknown`.

### Tracing dependencies

```console
$ drift importers src/lib/auth.ts
  src/app/page.ts  ../lib/auth: requireAuth
  src/app/login.ts  @/lib/auth: signIn, signOut
```

Prefer passing a file path. For JS and TS it resolves relative imports and `@/` or `~/` aliases, so `src/lib/auth.ts` won't match an import of `./oauth`. For Python it resolves module paths. Other aliases and Rust paths are not resolved, so search those by text, such as `drift importers forge_core`. Text matches any import source containing it, case-insensitively.

Each line shows the importing file, the import source, and the imported names. `*` means a wildcard or namespace import, and no names means a bare import, `require()` or dynamic `import()`. Re-exports such as `export { a } from './b'` count as imports.

## Symbol kinds

| Kind | Languages | Description |
|------|-----------|-------------|
| `function` | All | Functions, methods, and JS or TS consts holding a function |
| `class` | TS/JS, Python | Class definitions |
| `interface` | TS | Interface definitions |
| `type` | TS, Rust, Python, SQL | Type aliases, `CREATE TYPE` |
| `enum` | TS, Rust | Enum definitions |
| `const` | TS/JS, Python, Rust, SQL | Constants and variables, Rust statics, Python `ALL_CAPS` names, SQL indexes and policies |
| `struct` | Rust | Structs and unions |
| `trait` | Rust | Trait definitions |
| `impl` | Rust | Impl blocks, named `Type` or `Trait for Type` |
| `macro` | Rust | `macro_rules!` definitions |
| `module` | Rust, TS | Modules and namespaces |
| `table` | SQL | `CREATE TABLE` |
| `view` | SQL | `CREATE VIEW`, including materialized views |
| `procedure` | SQL | `CREATE PROCEDURE` |
| `trigger` | SQL | `CREATE TRIGGER` |

Schema-qualified SQL names keep their schema, such as `public.users`. To find one by its bare name, rely on the substring fallback in `drift query`.

## Symbol properties

| Property | Type | Description |
|----------|------|-------------|
| `name` | string | Symbol name |
| `kind` | string | One of the kinds above |
| `line` | int | 1-indexed first line |
| `end_line` | int or null | 1-indexed last line. Null for SQL |
| `exported` | bool | Whether the symbol is public (see below) |
| `async` | bool | Whether the function is async |
| `parent` | string or null | Enclosing class, impl type, trait, module, namespace or function |
| `decorators` | string[] | Decorator names without arguments (Python only) |

### What `exported` means

| Language | Exported when |
|----------|---------------|
| TS/JS | It has `export`, is named in `export { }` or `export default`, or is assigned through CommonJS `exports`. Methods count when their class is exported and they aren't `private`, `protected` or `#private` |
| Python | Its name has no leading underscore, or it is listed in `__all__` when the module defines one. Functions nested in functions never count |
| Rust | It has any `pub` modifier, including `pub(crate)`. Items in a trait follow the trait. Trait impl methods don't count |
| SQL | Always |

## Compact mode

When the index was generated with `--compact`:

- Null, false and empty fields are omitted
- The JSON has no whitespace
- `symbol_index` only contains exported symbols, and its entries omit `exported`

`files` still lists every symbol, so private symbols remain findable through `drift query` and `drift outline`. A direct lookup in `symbol_index` won't find them.

## Keeping the index fresh

`drift stats` shows when the index was generated. If that is older than your recent changes, re-run:

```bash
drift index . --compact
```

Indexing takes well under a second for most repos, so it's cheap to refresh.

## Integration examples

### Claude Code

Run `drift install .` to write `.claude/skills/drift/SKILL.md`. Claude Code loads it when working on supported file types.

### AGENTS.md, Cursor rules, Codex

Add to your agent instructions:

```
Before grepping or reading whole files, use Drift:
  drift query <symbol>     finds a definition
  drift outline <file>     lists a file's symbols and imports
  drift tests <text>       finds tests
  drift importers <path>   finds who imports a module
Read only the line ranges they print. Do not read .drift-index.json directly, because it is large.
```

### Programmatic access

For scripts that need more than the commands offer, load the file in your own code. `names` in `imports` is a list, the string `"*"`, or absent or null.

```python
import json

with open(".drift-index.json") as f:
    index = json.load(f)

# Find an exported symbol
for loc in index["symbol_index"].get("MyClass", []):
    print(f"{loc['file']}:{loc['line']}-{loc.get('end_line')} ({loc['kind']})")

# List a file's exports
file_data = index["files"]["src/main.ts"]
exports = [s for s in file_data["symbols"] if s.get("exported")]
```
